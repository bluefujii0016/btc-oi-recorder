# SAR Tracker 長期検証データセット

## このフォルダのルール(分析を始める前に必ず読む)

**このデータは、期間ごとに使い方が決まっている。確認期間と最終確認期間は、事前登録が終わるまで成績を計算しない。**
これは人間が分析する場合も、AIのセッションが分析する場合も同じ。
データを読み込んだら、最初に「探索期間」だけに絞り込んでから分析を始めること。

### 列の定義

| 列 | 内容 |
|---|---|
| `t` | 足の開始時刻(UNIX秒、UTC) |
| `datetime_utc` | `t` を人が読める形にしたもの |
| `open` / `high` / `low` / `close` | 確定足の始値・高値・安値・終値 |
| `volume` / `quote_volume` | 出来高(BTC) / 売買代金(USDT) |
| `trades` | 約定回数 |
| `taker_buy_volume` / `taker_buy_quote_volume` | テイカー買いの出来高(BTC / USDT) |
| `sar` / `af` / `ep` | その足が確定した時点のSAR値、加速係数、極値 |
| `trend` | up / down |
| `dots_since_flip` | N。転換した足を1とする |
| `reversed` | その足で転換したら1 |
| `trend_8h` / `trend_12h` / `trend_24h` | その足の終値と、8/12/24時間前の足の終値を比べた方向 |
| `candlestick_patterns` | `sar_tracker.py` の判定関数で検出したパターン。複数ある場合は `|` 区切り |

### 含まれていないデータ

- 清算データ(Bybit近似):2年分を遡れるかが未確認のため、含めていない。仮説④を検証できるのは、清算データがある期間だけになる
- 接近通知:実際に送られた通知の記録は存在しない。仮説⑥⑦は、判定条件を当てはめて計算で再現することになる。ただし今のしきい値は修正前の誤ったデータで決めたものなので、決め直しが必要
- OI、ロング/ショート比率、Funding Rate:必要になったら、`t` で結び付ける別ファイルとして追加する

## 2. 期間の区分

| 区分 | 期間(UTC) | 本数 | 転換 | 使い方 |
|---|---|---|---|---|
| **探索** | 2024-10-01 00:00 〜 2025-09-30 23:45 | 35,040 | 3,040 | 自由に分析してよい |
| **確認** | 2025-10-01 00:00 〜 2026-04-30 23:45 | 20,352 | 1,658 | 事前登録した候補を1回だけ評価する |
| **最終確認** | 2026-05-01 00:00 〜 2026-09-01 23:45 | 11,904 | 959 | 確認を通過した候補を1回だけ評価する |
| 既に見た期間 | 2026-09-02 00:00 〜 2026-10-01 06:45 | 2,812 | 236 | 2026-10-01 にすでに分析済み。検証には使わず、参考扱いにする |
| 前向き検証 | 2026-10-01 06:18 以降 | 蓄積中 | — | 稼働中の `sar_log.jsonl`。最後の関門 |

各区分の境界は、`t` を基準に判定する。たとえば探索期間なら `1727740800 <= t < 1759276800` となる。

## 3. 運用ルール

1. **探索期間**では、何を試してもよい。総当たりでも、仮説を後から思いついても構わない
2. 探索期間で、候補を**2〜3個まで**に絞り込む。絞り込んだら、事前登録文書に次の項目を固定する
   - エントリー条件
   - エグジット条件
   - 評価指標(主指標は期待値/回。手数料は往復0.05%を控除)
   - 合格基準
3. 事前登録が終わってから、**確認期間**で一度だけ評価する
4. 確認期間で合格した候補だけを、**最終確認期間**で一度だけ評価する
5. 確認期間や最終確認期間で不合格になった場合、その期間のデータを見ながらパラメータを調整し直してはいけない。新しい候補は探索期間に戻って作り直す
6. 確認期間と最終確認期間について、「価格の範囲」「転換の回数」といった、成績に関係しない情報を確認するのは構わない。勝率、期待値、MAE/MFE など、成績に関係するものは計算しない
7. 分析の結果を報告するときは、使った定義を必ず書いておく。期間、エントリーの価格、SL/TPの判定方法(ヒゲで判定するか、終値で判定するか)、同じ足の中でSLとTPの両方に届いた場合の扱い、手数料の仮定、など
